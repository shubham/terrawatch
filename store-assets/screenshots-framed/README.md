# Framed Play Store screenshots (Plan 5 Task 5)

Framed, captioned versions of `store-assets/screenshots/*.png` for the actual Play Console
upload. Generated by `scripts/frame-screenshots.py` (Pillow) — a dark device bezel around a
letterboxed/pillarboxed copy of the real capture (never stretched) with a caption strip
(kicker + honest headline) above it, on a 1080×1920 canvas.

## Re-run (one command)

```
python3 scripts/frame-screenshots.py
```

From the repo root, with no arguments. Reads `store-assets/screenshots/` +
`scripts/screenshots-config.json`, writes `store-assets/screenshots-framed/`. Re-run any time
either the source captures or the config change — it's fully idempotent (same inputs always
produce byte-identical outputs).

Optional flags if you need a different input/output/config location:

```
python3 scripts/frame-screenshots.py \
    --input-dir store-assets/screenshots \
    --output-dir store-assets/screenshots-framed \
    --config scripts/screenshots-config.json
```

Requires `python3` + Pillow (`pip install Pillow` — confirmed present at 11.3.0 on the machine
this was built on) and macOS's bundled Arial family under
`/System/Library/Fonts/Supplemental/` (see script docstring for the font-fallback behavior if
those aren't present on a different machine).

from the device matrices; `store-assets/listing.md` already made and documented that call (Plan 4

## Chrome cropping (documented, not silently done)

The 5 app-screen captures (1–5) have their OS status bar and OS 3-button nav row cropped before
framing — measured pixel boundaries (uniform-gray status bar 0–108px, solid nav-row band starting
~2296px), not eyeballed, and re-verified per-file by sampling actual pixel rows (see git history /
task report for the analysis). The app's **own** bottom tab bar (Home/History/Insights) sits above
that nav-row band and is deliberately kept — only OS chrome is removed, not app content. The
notification-shade capture (6) is cropped **nothing**: its clock/date and gesture drag-handle are
real shade content, not a duplicate status/nav bar, so cropping would have removed evidence, not
chrome. Exact per-shot `crop_top`/`crop_bottom` values and the reasoning for each live in
`scripts/screenshots-config.json`, not hardcoded in the script.

Because capture 6 isn't cropped the same way as 1–5, the six inputs aren't all the same aspect
ratio even before framing — this is exactly why the script fit-contains (scale to fit, center,
pillarbox) rather than resizing-to-fill: nothing is ever stretched/distorted, a narrower capture
just gets visible dark bars on the sides instead.

## Design decisions

- **Palette**: exact Calm Guardian hex values, hand-copied from
  `core/ui/src/commonMain/kotlin/com/yugma/terrawatch/ui/theme/Tokens.kt` (Ink `#17222E`, Canvas
  `#F6FAF9`, Water `#D9E9F4`, Safe `#2FA36B`, DuskCanvas `#10161D`, DuskCard `#1A222C`) — the same
  "hex values are LAW" token set every screen in the app itself sources from, not approximated.
- **Canvas background = Water** (`#D9E9F4`), matching `store-assets/feature-graphic.png`'s own
  "Water background, Ink bold text" convention, so the store listing reads as one consistent brand
  treatment rather than two unrelated ones.
- **Bezel is deliberately plain**: one dark rounded rect (DuskCanvas) with a slightly lighter inset
  panel (DuskCard) behind the screen area. No notch, no speaker grille, no side buttons — "simple,
  no fake hardware details" per this task's brief.
- **Font**: Arial / Arial Bold from `/System/Library/Fonts/Supplemental/` — confirmed present,
  clean and universally legible for a poster-style caption. Apple's SFNS was considered and
  rejected (intended for Apple system UI, not general-purpose rendering).
- **Headline auto-shrink**: font size steps down from 74px to a 44px floor until the headline wraps
  to at most 2 lines, so a longer caption on a future re-run can never clip — verified by rendering
  a deliberately long test headline during development.
- A small `TERRAWATCH` kicker (Safe green, small caps) sits above every headline for brand
  consistency across the set — not required by the brief, added as a tasteful, low-risk extra;
  easy to remove in `frame-screenshots.py`'s `render_shot()` if unwanted.

## Known limitations / stale-pending-fresh-capture

All 6 inputs predate this plan's own device-verification pass (98bc1cd8 was not connected for any
task this session) and predate several Plan 5 features entirely — **expected**, not a defect in
this framing pipeline, since the pipeline's job is to frame whatever the current best captures are
and re-run cleanly once fresher ones exist:

- **None of the 6 show Plan 5's new UI** — the my-location FAB (Task 1), favorite-city quick-switch
  chips (Task 2), or the feed live-reveal "N new quakes ↑" chip (Task 3b) appear in none of these
  captures, since all 6 source captures predate those tasks. Re-run this pipeline once fresh Plan 5
  device captures exist (same one command, new files in `store-assets/screenshots/` +
  `scripts/screenshots-config.json`, no code change needed).
- **`02-detail-sheet.png` specifically is stale relative to the in-app "In the news" section**
  (shipped Plan 4 Task 5, fixed Plan 5 Task 2b): this capture predates that feature and shows none
  of it. No populated-news device capture exists anywhere in this repo yet — every news-related
  capture on disk (`docs/qa/plan-4-device-matrix/task5-*.png`) shows a loading or
  hidden-after-GDELT-429 state, not a real successful news card, so there was nothing better to
  pick. The headline ("Every quake, the full picture") was written to match what's actually
  pictured, not the full feature set — no vaporware. Swap this slot once a real populated-news
  capture exists.
- The known Play-spec ratio note from `store-assets/listing.md` (raw captures at 1080×2400 being
  slightly over the documented 2:1 max) is now moot for these framed outputs — final canvas is
  1080×1920, 1.78:1, safely under the limit. The raw unframed captures in
  `store-assets/screenshots/` are unaffected and still carry that same disclosed limitation if used
  directly instead of these framed versions.
